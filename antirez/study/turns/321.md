### 🔍 Verifica dell'Equazione e dei Tipi

L'equazione algebrica formale del Blackbird è:

$$B_1 x y z w = x (y z w)$$

Ripercorrendo la tua implementazione:

1. `x` è una funzione unaria: `(arg: V) => R`.
2. `y` è una funzione binaria curificata: `(arg: T) => (arg: U) => V`.
3. `z` è il primo argomento per $y$, di tipo `T`.
4. `w` è il secondo argomento per $y$, di tipo `U`.
5. `y(z)(w)` viene valutato per primo, producendo un valore di tipo `V`.
6. Tale risultato viene passato a $x$, ottenendo il valore finale di tipo `R`.

---

### 🌟 Perché la gestione dei Generics è ottima

Distribuendo i generics nei due livelli di funzioni:
* `<V, R>` sulla prima funzione fissa i tipi dell'operazione esterna $x$.
* `<T, U>` sulla seconda funzione fissa i tipi degli argomenti d'ingresso per la funzione binaria $y$.

TypeScript riesce a inferire tutti i tipi al volo in modo **completamente type-safe**, senza bisogno di `any` o di cast espliciti.

---

### 💡 Cos'è il Blackbird ($B_1$)?

Mentre il combinatore Bluebird ($B$) compone due funzioni unarie ($B x y z = x(y(z))$), il **Blackbird ($B_1$)** è l'estensione del compositore per funzioni binarie:
> **Compone una funzione unaria $x$ con il risultato di una funzione binaria $y$.**

---

### 🎨 Esempio nel Picture Language

Il Blackbird è utilissimo quando vuoi combinare due pittori (con `beside` o `below`) e applicare una trasformazione globale (come `rotate90` o `flip_vert`) all'**intera composizione risultante**.

`​`​`typescript
const B1 =
  <V, R>(x: (arg: V) => R) =>
  <T, U>(y: (arg: T) => (arg: U) => V) =>
  (z: T) =>
  (w: U): R =>
    x(y(z)(w));

// Impostiamo:
// x = rotate90    (trasformazione unaria da applicare alla fine)
// y = beside      (combinatore binario)
// z = wavePainter
// w = roosterPainter

const rotatedComposition = B1(rotate90)(beside)(wavePainter)(roosterPainter);
