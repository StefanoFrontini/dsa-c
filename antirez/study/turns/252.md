## 🏗️ La Nuova Geometria: React + Attori

In un'applicazione React tradizionale, lo stato è "incastrato" dentro i componenti. Questo ti costringe a usare catene infinite di `useState`, `useEffect` e contesti globali solo per far parlare due bottoni tra loro. 

Nell'Actor Model, l'architettura si ribalta completamente:

* **React diventa un puro convertitore:** Il suo unico compito è prendere uno stato e sputare fuori HTML. Segue la formula matematica pura: $$UI = f(state)$$
* **I Componenti non pensano:** Un componente non decide cosa succede quando l'utente clicca un bottone. Si limita a fare un "postino": prende il clic e lo spara come evento all'attore di riferimento.
* **Addio `useState` (per la logica):** Non userai più `useState` per gestire la logica di business (es. `isDownloading`, `audioBuffer`, `playlist`). L'unica cosa che serve a React è un piccolo meccanismo di "ascolto" (*Subscription*) per sapere quando l'attore ha cambiato stato, in modo da ridisegnare la schermata.

## 💻 Il Matrimonio in Codice (Vanilla JS + React)

Prendiamo la fabbrica funzionale di attori che abbiamo progettato prima e colleghiamola a un componente React Vanilla. Per far capire a React che l'attore ha aggiornato lo stato e che deve rifare il rendering, usiamo l'hook nativo `useSyncExternalStore` (introdotto in React 18 proprio per connettere React a sistemi di stato esterni).

### 1. Modifichiamo leggermente l'attore funzionale per permettere le sottoscrizioni
L'attore ora deve solo permettere a chiunque (in questo caso a React) di registrarsi per ricevere gli aggiornamenti di stato.

`​`​`javascript
function creaAttore(statoIniziale, funzioneTransizione) {
    let statoAttuale = statoIniziale;
    const mailbox = [];
    const ascoltatori = new Set(); // I componenti React che ascoltano

    function svuotaMailbox() {
        if (mailbox.length === 0) return;
        const evento = mailbox.shift();
        
        const prossimoStato = funzioneTransizione(statoAttuale, evento);
        
        if (prossimoStato !== statoAttuale) {
            statoAttuale = prossimoStato;
            // Avvisiamo React che lo stato è cambiato!
            ascoltatori.forEach(callback => callback());
        }

        if (mailbox.length > 0) queueMicrotask(svuotaMailbox);
    }

    return {
        send: function(evento) {
            mailbox.push(evento);
            if (mailbox.length === 1) queueMicrotask(svuotaMailbox);
        },
        subscribe: function(callback) {
            ascoltatori.add(callback);
            return () => ascoltatori.delete(callback); // Funzione di clean-up
        },
        getSnapshot: function() {
            return statoAttuale;
        }
    };
}
`​`​`

### 2. Il Componente React diventa una View Pura
Guarda come diventa pulito, leggibile e privo di effetti collaterali (`useEffect`) il tuo componente React:

`​`​`jsx
import { useSyncExternalStore } from 'react';

// Creiamo l'attore del Player Audio fuori da React (vive nella sua memoria protetta)
const attorePlayer = creaAttore('STOPPED', comportamentoPlayer);

function BottonieraRadio() {
    // React si connette all'attore. Si re-innesca il render SOLO se l'attore cambia stato.
    const statoPlayer = useSyncExternalStore(
        attorePlayer.subscribe, 
        attorePlayer.getSnapshot
    );

    return (
        <div className="player-panel">
            <h3>Stato Radio: {statoPlayer}</h3>
            
            {statoPlayer === 'STOPPED' ? (
                <button onClick={() => attorePlayer.send({ type: 'PLAY' })}>
                    Play Live
                </button>
            ) : (
                <button onClick={() => attorePlayer.send({ type: 'STOP' })}>
                    Stop Radio
                </button>
            )}
        </div>
    );
}

## 🎯 I Vantaggi di questa separazione

1.  **I Test diventano un paradiso:** Per testare la logica della tua radio non devi più montare componenti React o usare librerie grafiche di testing. Ti basta testare la funzione `comportamentoPlayer`, che essendo una funzione pura, prende un input e dà un output prevedibile al 100%.
2.  **Performance Chirurgiche:** In un'app React normale, quando cambia lo stato in un componente in alto, tutta l'applicazione si ridisegna (*Re-render* a cascata). Con gli attori, solo i millimetrici componenti che si sono esplicitamente iscritti a quel singolo attore si aggiorneranno, lasciando il resto del DOM intatto.
3.  **Portabilità Assoluta:** La logica della tua radio scritta con gli attori funzionali è ora totalmente indipendente da React. Se un domani decidessi di buttare via React e passare a Svelte, SolidJS, o persino a un'applicazione mobile nativa, ti basterà copiare e incollare il file degli attori senza cambiare una virgola di logica.

Questo approccio svuota React della sua complessità e lo restituisce al suo scopo originario: essere una fantastica, dichiarativa e leggerissima libreria per disegnare pixel sullo schermo.
