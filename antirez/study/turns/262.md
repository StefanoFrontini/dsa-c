## 🕒 La Soluzione: Usare `poll()` come un Metronomo

Invece di dire a `poll()` di aspettare all'infinito (`-1`), gli diciamo: *"Aspetta che succeda qualcosa, ma se non succede nulla, svegliati comunque dopo al massimo 33 millisecondi"*.

Perché proprio **33 millisecondi**? 
Perché $1000 \text{ ms} / 30 \text{ fps} \approx 33 \text{ ms}$. Se impostiamo il timeout di `poll()` a 33 ms, garantiamo che il nostro ciclo giri *almeno* 30 volte al secondo, il tempo perfetto per disegnare un'animazione fluida nel terminale.

Se l'utente preme un tasto dopo soli 10 ms, `poll()` si sveglierà prima (reattività istantanea). Se l'utente non tocca nulla per ore, `poll()` continuerà a svegliarsi ogni 33 ms, aggiornerà l'animazione e si rimetterà a dormire.

## 🛠️ Come si scrive in C (L'Event Loop con Animazione)

Immaginiamo di voler mostrare un piccolo indicatore di caricamento che gira (`|`, `/`, `-`, `\`) mentre aspettiamo la musica o l'input dell'utente.

`​`​`c
#include <stdio.h>
#include <poll.h>

// I 4 fotogrammi della nostra animazione nel terminale
const char caricamento[] = {'|', '/', '-', '\\'};
int frame_attuale = 0;

void disegna_animazione(void) {
    // Stampiamo il carattere dell'animazione e usiamo \r per tornare all'inizio della riga
    printf("\r[Riproduzione in corso... %c] Premi 'a' per Play/Pause, 'q' per uscire: ", caricamento[frame_attuale]);
    fflush(stdout); // Forza il terminale a mostrare subito il carattere (essendo buffered)
    
    // Passiamo al fotogramma successivo
    frame_attuale = (frame_attuale + 1) % 4;
}

void event_loop_con_animazione(int socket_radio) {
    struct pollfd fds[2];
    fds[0].fd = STDIN_FILENO;
    fds[0].events = POLLIN;
    fds[1].fd = socket_radio;
    fds[1].events = POLLIN;

    long long ultimo_render = get_current_time_ms();
    int programma_attivo = 1;

    while (programma_attivo) {
        long long adesso = get_current_time_ms();
        
        // 1. Calcoliamo quanto tempo manca al prossimo fotogramma dell'animazione (es. ogni 100 ms)
        long long tempo_passato = adesso - ultimo_render;
        int tempo_al_prossimo_frame = 100 - tempo_passato;
        
        if (tempo_al_prossimo_frame < 0) {
            tempo_al_prossimo_frame = 0; // Dobbiamo renderizzare subito!
        }

        // 2. Il timeout di poll() diventa dinamico: aspetterà SOLO il tempo necessario per il prossimo frame
        int res = poll(fds, 2, tempo_al_prossimo_frame);

        // 3. Gestione degli eventi fisici (Rete o Tastiera)
        if (res > 0) {
            if (fds[0].revents & POLLIN) {
                char tasto;
                read(STDIN_FILENO, &tasto, 1);
                if (tasto == 'q') programma_attivo = 0;
                // Gestisci gli altri tasti...
            }
            if (fds[1].revents & POLLIN) {
                // Leggi i dati dalla rete...
            }
        }

        // 4. È ora di aggiornare l'animazione?
        adesso = get_current_time_ms();
        if (adesso - ultimo_render >= 100) {
            disegna_animazione();
            ultimo_render = adesso;
        }

        // Svuotamento mailbox e altre logiche degli attori
        svuota_mailbox_attori();
    }
}

## 🧠 Cosa succede sotto il cofano?

Questo approccio è un capolavoro di efficienza energetica:

* **Quando non succede nulla:** Il programma non consuma CPU. Il kernel lo tiene addormentato dentro `poll()` per blocchi precisi di 100 millisecondi. Allo scadere di ogni blocco, la CPU si sveglia per un microsecondo, cambia il carattere sullo schermo (`/` -> `-`), e si raddormenta immediatamente.
* **Quando l'utente interagisce:** Se premi "q" a metà di un fotogramma (dopo 40 ms), `poll()` interrompe l'attesa all'istante, legge il tasto e chiude il programma, senza farti aspettare la fine del timer dei 100 ms.

Hai appena scoperto come unire il **tempo discreto** (le animazioni, i frame rate) con il **tempo asincrono guidato da eventi** (la tastiera, i pacchetti di rete) usando un'unica, potentissima chiamata di sistema.

Questa flessibilità del `poll()` dinamico ti fa capire perché in C a basso livello si possano scrivere programmi incredibilmente complessi ed efficienti senza la necessità di appoggiarsi a pesanti framework esterni.
