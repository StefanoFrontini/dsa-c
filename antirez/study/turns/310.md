L'errore nasce dal fatto che TypeScript non riesce a inferire automaticamente il tipo di ritorno `R` dell'invocazione `M(self)`. 

Quando il compilatore valuta `M(self)`, non conoscendo il tipo preciso di `self`, attribuisce a `M(self)` il tipo di fallback **`unknown`**. In TypeScript non puoi invocare direttamente un oggetto di tipo `unknown` come se fosse una funzione (da qui l'errore `Object is of type 'unknown'`).

### La Soluzione Type-Safe

Per risolvere l'errore senza usare `any`, basta definire il tipo della funzione di step del frattale (`Step`) e usarlo per tipizzare `self`. In questo modo `M` saprà esattamente cosa restituisce `M(self)`.

`​`​`typescript
type Painter = (frame: any) => void;

// 1. Definiamo la firma della nostra funzione curryficata
type Step = (p: Painter) => (depth: number) => Painter;

// 2. Il nostro tipo di funzione auto-applicabile
type SelfApplicable<R> = (x: SelfApplicable<R>) => R;

// 3. Il Mockingbird
const M = <R>(x: SelfApplicable<R>): R => x(x);

// 4. Tipizziamo "self" come SelfApplicable<Step>
const makeFractal = (self: SelfApplicable<Step>): Step => 
  (p: Painter) => 
  (depth: number): Painter => {
    if (depth === 0) return p;

    // ✅ Ora M(self) viene inferito correttamente come "Step"!
    // TypeScript sa che può essere invocato con (p)(depth - 1)
    const smaller = M(self)(p)(depth - 1);

    return beside(p)(below(p)(smaller));
  };

// 5. Inneschiamo la ricorsione: "fractal" sarà di tipo Step
const fractal = M(makeFractal);

// Uso:
const waveFractal = fractal(wavePainter)(4);

### Cosa è cambiato?

Dichiarando `self: SelfApplicable<Step>`:
1. `M` riceve un argomento di tipo `SelfApplicable<Step>`.
2. Il generic `<R>` di `M` viene risolto istantaneamente in **`Step`** (ovvero `(p: Painter) => (depth: number) => Painter`).
3. L'espressione `M(self)` restituisce quindi un valore di tipo `Step`, che TypeScript ti permette di invocare immediatamente con i parametri `(p)` e `(depth - 1)`.
