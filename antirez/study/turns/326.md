### 🔍 Verifica dell'Equazione e dei Tipi

L'equazione algebrica formale dello Zebra Dove è:

$$ZD x y z w = x (y z) w$$

Ripercorrendo la tua implementazione:

1. `x` è una funzione binaria curificata: `(arg: U) => (arg: R) => V`.
2. `y` è una trasformazione unaria: `(arg: T) => U`.
3. `z` è l'argomento d'ingresso per $y$, di tipo `T`.
4. `w` è il secondo argomento per $x$, di tipo `R`.
5. `y(z)` produce un valore di tipo `U`.
6. `x(y(z))(w)` applica $x$ prima al valore trasformato `y(z)` e poi a `w`, restituendo il tipo finale `V`.

---

### 💡 Zebra Dove ($ZD$) vs Dove ($D$)

È interessante notare la perfetta dualità tra questi due combinatori:

* **Dove ($D$):** $D x y z w = x y (z w)$ $\rightarrow$ Trasforma solo il **secondo** argomento di $x$.
* **Zebra Dove ($ZD$):** $ZD x y z w = x (y z) w$ $\rightarrow$ Trasforma solo il **primo** argomento di $x$.

---

### 🎨 Esempio nel Picture Language

Nel *Picture Language*, lo Zebra Dove è utilissimo quando vuoi combinare due pittori diversi (es. con `beside` o `below`), ma vuoi applicare una trasformazione preliminare (come `rotate90` o `flip_vert`) **solo al primo pittore** lasciando il secondo invariato.

`​`​`typescript
const ZD =
  <U, R, V>(x: (arg: U) => (arg: R) => V) =>
  <T>(y: (arg: T) => U) =>
  (z: T) =>
  (w: R): V =>
    x(y(z))(w);

// Impostiamo:
// x = beside         (unisce due pittori affiancandoli)
// y = rotate90       (trasformazione da applicare al primo pittore)
// z = wavePainter    (primo pittore)
// w = roosterPainter (secondo pittore, invariato)

const resultPainter = ZD(beside)(rotate90)(wavePainter)(roosterPainter);
