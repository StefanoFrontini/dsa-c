Iniziare con un gruppo selezionato di **10-20 radio ad alta stabilità** è la strategia migliore per validare l'architettura del tuo player (C o WebAssembly) prima di passare a un database dinamico.

Per trovare gli URL di streaming — sia i flussi diretti MP3/AAC che le playlist HLS (`.m3u8`) — hai a disposizione tre strade principali.

---

## 🔍 Dove trovare gli URL di Streaming

### 1. Radio-Browser.info (L'API Open Source definitiva)
È il database pubblico più grande al mondo per le radio via internet (utilizzato anche da molte app commerciali). 
* **Perché è perfetto:** Mettono a disposizione un'**API JSON gratuita** e senza autenticazione.
* **Come usarlo:** Puoi fare una semplice richiesta HTTP per ottenere le radio italiane filtrate per clic o stabilità:
  `​`​`http
  GET https://de1.api.radio-browser.info/json/stations/bycountrycodeexact/IT
  `​`​`
* Ti restituirà una lista in JSON con nome, genere, favicon e soprattutto l'URL diretto dello stream.

### 2. Ispezione del Network (Chrome / Firefox DevTools)
Per le grandi radio commerciali (che spesso usano CDN protette o HLS), il metodo più immediato è "sniffare" la connessione mentre ascolti la radio sul loro sito ufficiale:
1. Apri la pagina del player ufficiale della radio (es. *Radio24*, *RTL 102.5*).
2. Apri i Developer Tools del browser (`F12`) e vai sulla scheda **Network** (Rete).
3. Filtra per **`Media`** oppure scrivi nella barra di ricerca del network: `.m3u8`, `.mp3`, `aac`, o `chunk`.
4. Avvia la riproduzione sulla pagina: vedrai comparire la richiesta HTTP allo stream audio.
5. Clicca con il tasto destro sul link e seleziona **Copy -> Copy link address**.

### 3. Repository e Playlist M3U su GitHub
La community open-source mantiene playlist aggregate aggiornate quotidianamente. Cercando su GitHub repository come **`iptv-org/iptv`** o "Italian Radio M3U", troverai elenchi `.m3u` o `.m3u8` formattati pronti da scaricare o parsare.

## ⚙️ HLS (`.m3u8`) vs Flussi Diretti (Icecast/Shoutcast): Cosa scegliere?

Mentre sviluppi il motore audio in C/Wasm, nota la differenza tra queste due tecnologie:

| Tipo di Flusso | Estensione / Protocollo | Stabilità dell'URL | Note per lo Sviluppatore |
| :--- | :--- | :--- | :--- |
| **Icecast / Shoutcast** | `.mp3` / `.aac` (es. HTTP con chunked encoding) | 🟢 **Altissima** (l'URL non cambia quasi mai) | È un flusso infinito di byte. Facilissimo da gestire in C con socket/OpenSSL. |
| **HLS (HTTP Live Streaming)** | `.m3u8` (Playlist di file `.ts` o `.aac`) | 🟡 **Media** (L'URL master è fisso, ma i segmenti scadono) | Richiede un parser per il file `.m3u8` e scarica i singoli frammenti via HTTP/HTTPS ogni pochi secondi. |

> **Consiglio per la fase iniziale:** Inizia integrando stazioni che forniscono flussi **MP3/AAC diretti su HTTP/HTTPS**. Gestire la decodifica di un flusso continuo di byte in C (tramite FFmpeg o libAV) è molto più semplice rispetto al parsing dinamico dei file di manifest HLS `.m3u8`.
