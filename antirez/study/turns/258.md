## 🕒 Come funziona l'Attore Timer

Nel browser (e nel sistema operativo sottostante), i timer non consumano cicli di CPU se gestiti in modo asincrono. Sfruttando la funzione nativa `setTimeout`, puoi dire al browser di gestire il conto alla rovescia in background, lasciando l'Event Loop completamente libero di far girare la UI a 60 FPS.

Il flusso dei messaggi durante un fallimento di rete diventerebbe questo:

`​`​`text
[Network Coordinator] ───(Errore Download)───► Cambia stato in [RETRY]
       │
       ├───(Invia Messaggio)───► [Attore Timer] ("Svegliami tra 5s")
       ▼
[Torna in IDLE/Ascolto] ◄───(Libera la CPU, l'Event Loop respira)
       │
       ▼ (Passano 5 secondi in background)
[Attore Timer] ───(Messaggio: TIME_ELAPSED)───► [Network Coordinator]
       │
       ▼ (Riceve la lettera)
[Network Coordinator] ───► Riesegue la Fetch del chunk
`​`​`

## 🛠️ La Macchina a Stati del Network Coordinator (In JS Funzionale)

Vediamo come si traduce in codice questo comportamento puro. Il `Network Coordinator` gestirà i macro-stati HLS che hai proposto, reagendo all'evento `TIME_ELAPSED` inviato dal timer.

`​`​`javascript
// La funzione comportamento (transizione) del Network Coordinator
function comportamentoNetwork(stato, evento) {
    switch (stato) {
        case 'IDLE':
            if (evento.type === 'AVVIA_RADIO') {
                console.log("Inizio il download della Master Playlist...");
                // Qui deleghi il download all'attore sotto-posto (Fetch Worker)
                attoreFetcher.send({ type: 'SCARICA_URL', url: 'playlist.m3u8' });
                return 'MASTER_PLAYLIST_DOWNLOADING';
            }
            break;

        case 'MASTER_PLAYLIST_DOWNLOADING':
            if (evento.type === 'DOWNLOAD_OK') {
                console.log("Master Playlist scaricata. Passo alla Sub-Playlist...");
                attoreFetcher.send({ type: 'SCARICA_URL', url: evento.payload.subUrl });
                return 'SUB_PLAYLIST_DOWNLOADING';
            }
            if (evento.type === 'DOWNLOAD_FALLITO') {
                console.log("Errore Master Playlist. Avvio Timer di RETRY di 5 secondi...");
                
                // PILLOLA ACTOR MODEL: Inviamo il messaggio all'attore Timer
                attoreTimer.send({ 
                    type: 'AVVIA_TIMER', 
                    durata: 5000, 
                    destinatario: attoreNetwork 
                });
                
                // Conserviamo nello stato cosa stavamo facendo per sapere cosa riprovare
                return { fase: 'RETRY', daRipetere: 'MASTER_PLAYLIST_DOWNLOADING' };
            }
            break;

        case 'RETRY':
            // Se l'utente preme STOP mentre siamo in attesa del retry, lo gestiamo!
            if (evento.type === 'STOP_UTENTE') {
                console.log("Radio fermata dall'utente durante l'attesa di retry.");
                return 'IDLE';
            }
            
            // Il messaggio non bloccante che arriva dall'Attore Timer dopo 5 secondi
            if (evento.type === 'TIME_ELAPSED') {
                console.log("5 secondi passati. Riprovo il download...");
                // In base a cosa era fallito, rilanciamo la fetch corretta
                if (stato.daRipetere === 'MASTER_PLAYLIST_DOWNLOADING') {
                    attoreFetcher.send({ type: 'SCARICA_URL', url: 'playlist.m3u8' });
                    return 'MASTER_PLAYLIST_DOWNLOADING';
                }
            }
            break;
            
        // ... qui gestirai SUB_PLAYLIST_DOWNLOADING e CHUNK_AUDIO_DOWNLOADING ...
    }
    return stato;
}

## 🛠️ Come si scrive l'Attore Timer Funzionale?

L'Attore Timer è un meraviglioso esempio di come un concetto dell'Actor Model possa fare da "ponte" con le API asincrone del browser. Sfrutta una closure per isolare il `setTimeout`:

`​`​`javascript
const attoreTimer = creaAttore({}, (statoLocale, evento) => {
    if (evento.type === 'AVVIA_TIMER') {
        const { durata, destinatario } = evento.payload;
        
        // Il browser gestisce questo timer in background a costo CPU = 0
        setTimeout(() => {
            // Allo scadere del tempo, inseriamo il messaggio nella mailbox del destinatario
            destinatario.send({ type: 'TIME_ELAPSED' });
        }, durata);
    }
    return statoLocale;
});
`​`​`

## 💎 I Vantaggi di questa architettura Temporale

1.  **Reattività Totale (Zero Freeze):** Durante quei 5 secondi di attesa nel macro-stato `RETRY`, il thread non è fermo su una riga di codice. L'Event Loop è vuoto. La UI del browser può processare animazioni, click e scorrimenti senza un singolo millisecondo di ritardo.
2.  **Gestione dei cambi di idea dell'utente:** Se l'utente clicca freneticamente sul pulsante "Stop" mentre la radio sta aspettando i 5 secondi per riprovare, il `Network Coordinator` riceve immediatamente il messaggio `STOP_UTENTE` nella sua mailbox, transiziona in `IDLE` e ignorerà il messaggio `TIME_ELAPSED` quando arriverà in ritardo, evitando download fantasma.
3.  **Ingegneria Elegante:** Hai rimosso la nozione di "tempo lineare cronologico" dal codice di rete. Il `Network Coordinator` ragiona solo per eventi discreti: non sa come passino quei 5 secondi, sa solo che a un certo punto riceverà una notifica chiamata `TIME_ELAPSED`.

Questo modo di progettare sposta la complessità dalla gestione dell'hardware (orologi, blocchi di thread) alla pura logica di flusso dei messaggi. È esattamente il tassello che mancava per rendere la tua pipeline HLS asincrona a prova di bomba.
