## 🎯 Perché il "Salto a livello di Chunk" è la scelta vincente

Nel tuo messaggio precedente hai calcolato che un chunk di Radio 24 dura esattamente **6,82667 secondi**. 
Se l'utente clicca "Avanti", saltare al chunk successivo significa spostare la riproduzione in avanti di circa 6,8 secondi. È un valore talmente vicino ai 5 secondi richiesti che l'utente finale non noterà alcuna differenza pratica: per lui sarà un perfetto ed elegantissimo tasto "Sali in avanti".

### Il vantaggio crudo in C: Allineamento dei Byte
Come abbiamo visto, i file `.ts` sono composti da pacchetti rigidi di 188 byte che iniziano sempre con il carattere di sincronizzazione `0x47`. 
Poiché i tuoi `chunk_offsets` memorizzano esattamente il punto in cui il Network Thread ha iniziato a scrivere il file in RAM, saltare su un offset significa **garantire a FFmpeg di atterrare sul primo byte pulito del file**.

## ⚠️ La trappola del "Salto esatto di 5 secondi"

Cosa succederebbe se tu volessi implementare un salto matematico di *esattamente* 5,00 secondi basandoti sui byte?
Dovresti calcolare quanti byte occupa mediamente un secondo di streaming (bitrate / 8) e moltiplicarlo per 5, ottenendo un numero di byte (es. 42.000 byte). Se tu facessi:
`​`​`c
ctx->parser.audio_buf.tail += 42000; // SBAGLIATO!
`​`​`
Andresti incontro a un disastro acustico. Cadendo a caso in mezzo al Ring Buffer, c'è il 99.9% di probabilità che tu vada a tagliare a metà un pacchetto MPEG-TS da 188 byte o, peggio, a metà un frame audio compresso AAC. 
Quando FFmpeg riceverà quei byte mutilati, inizierà a sputare sul tuo terminale Kubuntu centinaia di errori di decodifica (`Corrupted packet`, `Header missing`, `Invalid decode frame`), ammutolendo il player finché non riesce a trovare, per puro caso, un nuovo punto di sincronizzazione.

## 🛠️ Come implementarlo nel codice (Attento alla trappola dei due Thread!)

C'è un unico dettaglio a cui devi prestare massima attenzione: **il download corre più veloce della riproduzione**.
Mentre tu stai ascoltando il chunk 0, il tuo Network Thread potrebbe aver già scaricato ed elencato in memoria tutti i 99 chunk. Pertanto, la variabile `audioCounter` (che usi per scaricare) si troverà già a valore `99`. 

Non puoi usare `audioCounter` per sapere cosa stai ascoltando! Devi introdurre una nuova variabile nella tua `struct Parser` che tenga traccia di quale chunk l'Audio Thread stia materialmente decodificando:

`​`​`c
typedef struct Parser {
    // ... i tuoi buffer ...
    int chunk_offsets[99];
    int current_playing_chunk; // <-- NUOVO: Traccia il chunk in riproduzione
} Parser;
`​`​`

### 1. Aggiornare il chunk in riproduzione
Dentro la tua callback `read_packet`, ogni volta che FFmpeg ti chiede byte, puoi controllare se la `tail` ha superato l'offset del chunk successivo per aggiornare il contatore:

`​`​`c
// Se la tail ha superato l'inizio del chunk successivo, significa che siamo passati al prossimo pezzo!
if (ctx->parser.current_playing_chunk < 98 && 
    ctx->parser.audio_buf.tail >= ctx->parser.chunk_offsets[ctx->parser.current_playing_chunk + 1]) {
    ctx->parser.current_playing_chunk++;
}
`​`​`

### 2. La funzione per i bottoni "Avanti" e "Indietro"
Ora che hai l'indice esatto del chunk che l'utente sta ascoltando, scrivere la logica per i bottoni diventa una passeggiata. Ricordati che, come per il "Torna alla diretta", devi sempre **ripulire i tubi** (fare il *flushing*) dopo aver mosso i puntatori!

`​`​`c
void skip_chunk(Ctx *ctx, int direzione, AVFormatContext *fmt_ctx, AVCodecContext *codec_ctx, SDL_AudioStream *sdl_stream) {
    // direzione: +1 per andare avanti, -1 per andare indietro
    int target_chunk = ctx->parser.current_playing_chunk + direzione;

    // Controllo di sicurezza per non uscire dai 99 chunk scaricati
    if (target_chunk < 0 || target_chunk > 98) {
        printf("[SKIP] Limite raggiunto, impossibile saltare.\n");
        return;
    }

    // 1. MUOVIAMO LA TAIL: Saltiamo chirurgicamente all'offset del chunk bersaglio
    ctx->parser.audio_buf.tail = ctx->parser.chunk_offsets[target_chunk];
    ctx->parser.current_playing_chunk = target_chunk;

    // 2. PULIZIA DEI TUBI (Identica al salto della diretta)
    avio_flush(fmt_ctx->pb);
    avcodec_flush_buffers(codec_ctx);
    SDL_ClearAudioStream(sdl_stream);

    printf("[SKIP] Saltato al chunk %d (~6.8s %s)\n", 
           target_chunk, (direzione > 0) ? "avanti" : "indietro");
}
`​`​`

Se l'utente premerà il bottone "Avanti", chiamerai `skip_chunk(ctx, 1, ...)`. Se premerà "Indietro", chiamerai `skip_chunk(ctx, -1, ...)`.
