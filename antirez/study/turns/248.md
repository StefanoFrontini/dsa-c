Sfondi una porta aperta. JavaScript nasce originariamente come un linguaggio funzionale (fortemente ispirato a Scheme) mascherato con una sintassi che ricorda Java. Per questo motivo, l'approccio funzionale con strutture dati pure e funzioni non solo è possibile, ma è spesso considerato il modo più elegante e vicino alla filosofia originale di Erlang per implementare l'Actor Model.

Se in C la tua arma segreta per l'isolamento dei dati sono le `struct` e i puntatori passati esplicitamente (`Actor *self`), in JavaScript la superpotenza equivalente si chiama **Closure (Chiusura)**. 

Una closure permette a una funzione di "congelare" e racchiudere delle variabili all'interno del suo perimetro logico, rendendole totalmente invisibili e inaccessibili dall'esterno. Diventano, a tutti gli effetti, lo stato privato dell'attore.

## 🛠️ L'approccio Funzionale in JavaScript (Stile C)

Vediamo come convertire la classe di prima in una fabbrica di attori pura (*Factory Function*) che gestisce strutture dati grezze.

### 1. La Struttura Dati dell'Evento (Il Messaggio)
In JS non servono le `struct`, usiamo i Plain Old JavaScript Objects (POJO):
`​`​`javascript
// Semplici oggetti letterali, esattamente come le struct del C
const creaEvento = (type, payload = null) => ({ type, payload });
`​`​`

### 2. La Fabbrica degli Attori (Sfruttando le Closure)
Invece di una classe, creiamo una funzione che genera l'attore. Lo stato privato e la mailbox vivono nello scope della funzione e l'esterno può interagire con l'attore solo chiamando la funzione `send` restituita.

`​`​`javascript
function creaAttore(statoIniziale, funzioneTransizione) {
    // Variabili private protette dalla closure. 
    // Equivalgono ai campi della struct Actor in C.
    let statoAttuale = statoIniziale;
    const mailbox = [];

    // La funzione per processare la mailbox (Il nostro "Dispatch")
    function svuotaMailbox() {
        if (mailbox.length === 0) return;
        
        const evento = mailbox.shift();
        
        // Eseguiamo la funzione di transizione pura.
        // Passiamo lo stato attuale e l'evento. La funzione restituirà il nuovo stato.
        statoAttuale = funzioneTransizione(statoAttuale, evento);

        // Se ci sono altri messaggi, continuiamo al prossimo microtask
        if (mailbox.length > 0) {
            queueMicrotask(svuotaMailbox);
        }
    }

    // L'unica interfaccia pubblica dell'attore: la funzione per inviare messaggi
    return function send(evento) {
        mailbox.push(evento);
        // Se è il primo messaggio in coda, avviamo il ciclo di svuotamento
        if (mailbox.length === 1) {
            queueMicrotask(svuotaMailbox);
        }
    };
}
`​`​`

## 🎭 Come si definiscono i Comportamenti (Le Funzioni Pure)

Ora il comportamento dell'attore è una funzione matematica pura: riceve lo stato vecchio, riceve l'evento, e sputa fuori lo stato nuovo. Non tocca variabili globali, non fa *side-effects* diretti sulla memoria altrui.

Prendiamo come esempio l'**Attore Player** del tuo progetto:

`​`​`javascript
// Una funzione comportamento pura in stile macchina a stati
function comportamentoPlayer(stato, evento) {
    switch (stato) {
        case 'STOPPED':
            if (evento.type === 'PLAY') {
                console.log("Avvio riproduzione hardware...");
                return 'PLAYING'; // Restituisce il nuovo stato
            }
            break;
            
        case 'PLAYING':
            if (evento.type === 'STOP') {
                console.log("Arresto riproduzione hardware...");
                return 'STOPPED';
            }
            break;
    }
    return stato; // Se l'evento non è gestito, lo stato non cambia
}

// Creiamo l'istanza dell'attore
const attorePlayer = creaAttore('STOPPED', comportamentoPlayer);
`​`​`

Per inviare il messaggio, ora non hai nemmeno bisogno di chiamare un metodo di un oggetto. L'attore *è* una funzione esso stesso:

`​`​`javascript
// Invio di messaggi asincroni e disaccoppiati
attorePlayer(creaEvento('PLAY'));
attorePlayer(creaEvento('STOP'));
`​`​`

## ⚖️ C vs JavaScript: Il parallelismo geometrico

Se metti lo specchio tra i due linguaggi, noterai una simmetria concettuale impressionante:

* **In C:** La funzione ha bisogno del puntatore esplicito `(Actor *self)` perché le funzioni in C sono "orfane", non hanno memoria di dove sono nate. Devono ricevere la struttura dati da manipolare dall'esterno.
* **In JavaScript:** La closure elimina la necessità di passare `self` o di usare la parola chiave `this`. La funzione interna `svuotaMailbox` sa già dove si trovano `statoAttuale` e `mailbox` perché sono intrappolate nel suo stesso guscio di nascita.

Questo approccio funzionale elimina i difetti tipici della programmazione a oggetti (come i problemi di scope legati al `this` in JavaScript) e rende il codice incredibilmente modulare. Ogni attore diventa una fabbrica isolata e le funzioni comportamento possono essere spostate, ereditate o testate iniettando semplicemente input finti.
