---

### I due problemi nel tuo codice

1. **Sintassi dei tipi non valida (`U => V`):**
   In TypeScript le firme di tipo delle funzioni richiedono sempre le parentesi e il nome del parametro. Scrivere `U => V` è un errore sintattico; la forma corretta è `(arg: U) => V`.

2. **Il paradosso dell'auto-applicazione (`y(y)`):**
   Come abbiamo visto per il Mockingbird ($M$), l'operazione $y(y)$ applica una funzione a se stessa. TypeScript non è in grado di inferire un tipo ricorsivo infinito per i parametri senza l'uso di `any` o di un'interfaccia ricorsiva esplicita.

---

### La versione corretta e pulita in TypeScript

Per implementare il **Lark ($L$)**, la soluzione migliore è tipizzare $x$ in modo preciso (prende il risultato di $y(y)$ di tipo $R$ e restituisce $V$) e usare `any` per l'argomento auto-applicato $y$:

`​`​`typescript
// Lark: Lxy = x(yy)
const L = <R, V>(x: (arg: R) => V) => (y: any): V => x(y(y));
`​`​`

Se vuoi rendere ancora più evidente il legame con gli altri combinatori, puoi esprimere $y(y)$ usando direttamente il Mockingbird $M$:

`​`​`typescript
const L = <R, V>(x: (arg: R) => V) => (y: any): V => x(M(y));
`​`​`

---

### Dimostrazione della riduzione

L'equazione algebrica del Lark è:
$$L x y = x (y y)$$

1. Invocando `L(x)` forniamo la funzione esterna $x$.
2. Invocando `L(x)(y)` forniamo $y$.
3. Viene eseguito prima $y(y)$ (o $M(y)$), e il valore generato viene passato immediatamente a $x$.
