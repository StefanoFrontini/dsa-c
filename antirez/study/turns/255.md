Questa è la vera epifania dell'architettura a componenti. Trasformare ogni elemento della pagina in un attore granulare funzionale significa trattare il DOM del browser non come un blocco unico di grafica, ma come un ecosistema di **micro-servizi indipendenti** che galleggiano nell'Event Loop.

In questo modello, i tag HTML personalizzati (*Custom Elements*) fanno solo da guscio fisico, mentre la logica di transizione funzionale basata sulle closure governa la vita interna del componente.

Andiamo a smontare la meccanica logica di questa architettura atomica.

---

## 📐 La Mappa delle Responsabilità

Nel nostro audio player, non avremo più un file centrale che sa tutto. Avremo un **Attore Core** (invisibile, che gestisce lo stato del player) e tanti **Attori UI** visibili nella pagina.

Ecco come si dividono il lavoro:
* **L'Attore Core (`attorePlayer`):** È il cervello. Riceve i comandi, decide se passare da `STOPPED` a `PLAYING`, coordina FFmpeg. Non sa come è fatta la pagina web, non gli importa se c'è un bottone o un link. Lui sputa solo aggiornamenti di stato.
* **Gli Attori UI (`<status-text>`, `<play-button>`):** Sono i soldati semplici. Ognuno di loro si iscrive alle notifiche dell'Attore Core. Quando l'Attore Core cambia stato, ogni piccolo attore UI riceve il messaggio nella sua mailbox e aggiorna esclusivamente la sua piccolissima porzione di HTML.

---

## 🛠️ L'Implementazione in Vanilla JS Funzionale

Usiamo i **Web Components nativi** come guscio protettivo. All'interno del loro ciclo di vita (`connectedCallback`), creiamo l'attore funzionale tramite la closure.

### 1. L'Attore UI "Testo dello Stato" (`<status-text>`)
Questo componente deve solo mostrare la scritta "In riproduzione" o "Fermato". Non fa nient'altro.

`​`​`javascript
customElements.define('status-text', class extends HTMLElement {
    connectedCallback() {
        // 1. Definiamo il comportamento (la funzione di transizione pura)
        const comportamentoLocle = (statoElemento, evento) => {
            if (evento.type === 'STATO_AUDIO_VARIATO') {
                // Aggiornamento chirurgico del DOM nativo
                this.textContent = `Stato attuale: ${evento.payload}`;
                return { testo: evento.payload };
            }
            return statoElemento;
        };

        // 2. Creiamo l'istanza dell'attore legata a questo specifico tag HTML
        // Usa la stessa funzione factory "creaAttore" che abbiamo progettato prima
        const send = creaAttore({ testo: 'STOPPED' }, comportamentoLocle);

        // 3. Ci abboniamo all'Attore Core della Radio.
        // Quando il cervello cambia stato, invia un messaggio alla mailbox di questo componente
        this.unsubscribe = attorePlayer.subscribe(() => {
            const snapshotCore = attorePlayer.getSnapshot(); // es. 'PLAYING'
            send({ type: 'STATO_AUDIO_VARIATO', payload: snapshotCore });
        });

        // Inizializzazione grafica iniziale
        this.textContent = `Stato attuale: ${attorePlayer.getSnapshot()}`;
    }

    disconnectedCallback() {
        // Se il tag viene rimosso dalla pagina, ci disiscriviamo per evitare memory leak
        this.unsubscribe();
    }
});
`​`​`

### 2. L'Attore UI "Pulsante di Controllo" (`<play-button>`)
Questo attore fa la cosa opposta: non solo ascolta il cervello per cambiare la sua scritta da "Play" a "Stop", ma intercetta il clic dell'utente e spara un messaggio *all'indietro* verso il cervello.

`​`​`javascript
customElements.define('play-button', class extends HTMLButtonElement {
    connectedCallback() {
        const comportamentoBottone = (statoBottone, evento) => {
            if (evento.type === 'STATO_AUDIO_VARIATO') {
                this.textContent = evento.payload === 'PLAYING' ? 'Stop Radio' : 'Avvia Radio';
                this.className = evento.payload === 'PLAYING' ? 'btn-stop' : 'btn-play';
                return { modalita: evento.payload };
            }
            return statoBottone;
        };

        const send = creaAttore({ modalita: 'STOPPED' }, comportamentoBottone);

        // Ascolta il cervello per cambiare grafica
        this.unsubscribe = attorePlayer.subscribe(() => {
            send({ type: 'STATO_AUDIO_VARIATO', payload: attorePlayer.getSnapshot() });
        });

        // Intercetta il clic dell'utente e invia un messaggio all'Attore Core
        this.addEventListener('click', () => {
            const statoAttuale = attorePlayer.getSnapshot();
            const prossimoComando = statoAttuale === 'PLAYING' ? 'STOP' : 'PLAY';
            
            // Comunichiamo con il cervello via Actor Model puro
            attorePlayer.send({ type: prossimoComando });
        });

        this.textContent = attorePlayer.getSnapshot() === 'PLAYING' ? 'Stop Radio' : 'Avvia Radio';
    }

    disconnectedCallback() {
        this.unsubscribe();
    }
}, { extends: 'button' }); // Estendiamo il tag button nativo
`​`​`

## 💎 Perché questa architettura è un'opera d'arte

Se guardi la tua pagina HTML, ora puoi comporre l'interfaccia della tua radio semplicemente scrivendo questo nel file `.html`:

`​`​`html
<div className="player-container">
    <status-text></status-text>
    <button is="play-button"></button>
</div>
`​`​`

### I tre vantaggi cosmici di questo approccio:

* **Isolamento totale dei guasti:** Se il pulsante si rompe per un errore di sintassi, l'attore `<status-text>` continua a funzionare perfettamente. Le mailbox sono isolate e l'Event Loop salta l'attore corrotto passando al successivo.
* **Manutenzione a impatto zero:** Vuoi aggiungere una barra di progresso o un analizzatore di spettro grafico? Ti basta creare un nuovo attore `<audio-visualizer>`, farlo iscrivere all'Attore Core e buttarlo nell'HTML. **Non devi modificare nemmeno una riga di codice** dei componenti già esistenti. L'applicazione cresce per *addizione*, mai per modifica.
* **Addio Spaghetti Code:** Non esiste più un file di "colla" o di "regia" che prende i dati da un punto e li spinge in un altro. I componenti nascono, si attaccano ai canali di comunicazione degli attori di cui hanno bisogno, e vivono la loro vita in totale autonomia.

Questo è il massimo livello di disaccoppiamento raggiungibile nel frontend. Rende il codice pulito tanto quanto i sistemi distribuiti server-side in Erlang.
