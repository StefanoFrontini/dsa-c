## 🧵 1. Web Worker: È davvero un thread dello stesso processo?

**Sì, la tua intuizione è corretta.** 

Quando istanzi un **Dedicated Web Worker** (il tipo standard che crei con `new Worker()`), il browser crea un **nuovo thread del sistema operativo**. 

* **Stesso Processo:** Questo nuovo thread vive e viene eseguito **all'interno dello stesso identico processo del sistema operativo** (il *Renderer Process* della tua scheda/tab). 
* **Perché è importante:** Condividendo lo stesso processo, il Worker consuma pochissima memoria aggiuntiva rispetto a un intero processo. Tuttavia, proprio perché i thread all'interno di un processo condividono lo spazio di indirizzamento, il browser applica una sandbox logica rigida: non puoi accedere direttamente al DOM o alle variabili del Main Thread dal Worker, ma devi comunicare scambiando messaggi con `postMessage` (il nostro pattern Actor).

## 📦 2. WebAssembly: È un thread a sé stante?

Qui c'è una distinzione concettuale importantissima da fare: **No, un modulo WebAssembly (Wasm) non è un thread (e nemmeno un processo).**

WebAssembly è semplicemente **codice compilato** (bytecode altamente ottimizzato), privo di una propria entità di esecuzione autonoma.

* **Su quale thread gira?** Gira esclusivamente sul thread che lo invoca.
    * Se carichi ed esegui un modulo Wasm nel Main Thread (UI), il calcolo Wasm girerà sul Main Thread e, se pesante, bloccherà l'interfaccia.
    * Se vuoi far girare Wasm su un thread separato, **devi istanziarlo all'interno di un Web Worker**. In quel caso, Wasm girerà sul thread del Worker.
* **I "Wasm Threads":** Esiste una specifica di WebAssembly per il multi-threading (che ti permette di usare le API di `pthread` in C/C++ compilando in Wasm). Sotto il cofano, però, anche questa specifica non crea "thread Wasm" magici, ma **mappa i thread di C++ su una flotta di Web Worker JavaScript** che condividono la stessa memoria tramite `SharedArrayBuffer`.

## 🔒 3. Mojo IPC: Può usarlo lo sviluppatore web?

La risposta breve è: **No, non su una normale pagina web pubblica.**

**Mojo** è l'infrastruttura di comunicazione inter-processo (IPC) proprietaria e interna di Chromium (il motore di Chrome e Edge). 

Esistono delle API JavaScript per Mojo (chiamate **MojoJS**), ma **sono rigorosamente disabilitate per le normali pagine web per motivi di sicurezza monumentali**. 
> **Il rischio sicurezza:** Mojo permette di parlare direttamente con i processi ad alto privilegio del browser (come il processo Kernel/Browser o il processo GPU). Se una normale pagina web potesse usare MojoJS, un hacker potrebbe facilmente evadere dalla sandbox del browser e prendere il controllo del computer dell'utente. Molti degli exploit storici di Chrome cercano proprio di abilitare abusivamente MojoJS per fare "Sandbox Escape".

### In quali casi speciali viene usato MojoJS?
Ci sono scenari molto specifici in cui MojoJS viene abilitato e utilizzato:

1.  **Pagine Interne del Browser (`chrome://`):** Le pagine WebUI interne di Chrome (come `chrome://downloads` o `chrome://settings`) sono scritte in HTML/JS, ma hanno bisogno di comandare il browser a basso livello. Loro utilizzano MojoJS (generato a tempo di compilazione) per parlare con il core in C++.
2.  **Sviluppo di Browser Custom (Electron/CEF/Chromium forks):** Se stai creando il *tuo* browser personalizzato, una tua console o un'applicazione desktop embedded modificando il codice sorgente di Chromium, puoi usare i file `.mojom` per definire nuove API e fare in modo che la tua UI in JavaScript parli in modo asincrono ed efficiente con i tuoi servizi scritti in C++ o Rust.

## 🎯 Ricapitolando per il tuo progetto

Per l'architettura del tuo lettore video/audio nel browser:
* Creerai dei **Web Worker** (che sono i tuoi thread nel processo tab).
* Dentro uno di questi Worker caricherai il modulo **WebAssembly** di FFmpeg per fargli fare la decodifica pesante senza toccare la UI.
* Per far parlare la UI (Main Thread) con il Worker, utilizzerai lo standard web **`postMessage()`** (che dietro le quinte, a livello nativo nel codice C++ di Chrome, userà proprio Mojo per spostare i dati, ma tu lo vedrai come una semplice API JavaScript).
