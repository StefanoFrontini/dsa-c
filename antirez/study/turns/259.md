Sì, è assolutamente possibile ed è esattamente il modo in cui sono scritti i motori di rete industriali come **Nginx, Redis, o la libreria `libuv`** (che fa girare Node.js). 

In un'architettura single-thread in C, non usiamo thread separati del sistema operativo per ogni timer. Sfruttiamo invece una caratteristica fondamentale dei multiplexer di I/O come **`select()` o `poll()`**: la capacità di accettare un **timeout dinamico**.

Invece di lasciare che il thread si addormenti ciecamente con `sleep()`, diciamo a `poll()` di svegliarsi *al massimo* dopo 5 secondi, a meno che non arrivino prima dei dati dalla rete.

Ecco la ricetta ingegneristica per implementare i timer asincroni nel tuo Event Loop in C.

---

## 📦 1. La Struttura Dati del Timer

Per prima cosa ci serve una funzione per ottenere il tempo attuale in millisecondi e una struttura dati per registrare il nostro timer (un "promemoria" per l'Event Loop).

`​`​`c
#include <time.h>
#include <sys/time.h>

// Funzione di utilità per avere il tempo attuale in millisecondi
long long get_current_time_ms(void) {
    struct timeval tv;
    gettimeofday(&tv, NULL);
    return (long long)(tv.tv_sec) * 1000 + (tv.tv_usec / 1000);
}

typedef struct {
    long long expiration_time; // Il timestamp (ms) in cui il timer deve scattare
    int active;
    Actor *target_actor;       // L'attore da svegliare (es. Network Coordinator)
} AsyncTimer;

// Il nostro registro globale dei timer (per ora ne basta uno per il retry)
AsyncTimer retry_timer = {0};

## 🕒 2. Come l'Attore chiede il Timer: `set_timeout`

Quando l'attore Network Coordinator incontra un errore, calcola il tempo futuro in cui vuole essere svegliato, compila la struttura e rimette il controllo all'Event Loop. **Nessun blocco.**

`​`​`c
void avvia_timer_retry(Actor *network_actor, int delay_ms) {
    retry_timer.expiration_time = get_current_time_ms() + delay_ms;
    retry_timer.target_actor = network_actor;
    retry_timer.active = 1;
    
    printf("[TIMER] Programmato retry tra %d ms\n", delay_ms);
}
`​`​`

## 🔄 3. L'integrazione nell'Event Loop (`poll` dinamico)

Questo è il cuore della magia. Prima di chiamare `poll()` (o `select()`), l'Event Loop controlla se ci sono timer attivi. 
* Se c'è un timer che scade tra 5 secondi, imposta il timeout di `poll` a 5000 ms.
* Se non ci sono timer, imposta il timeout a `-1` (attendi all'infinito finché non arrivano dati).

`​`​`c
while (programma_attivo) {
    long long adesso = get_current_time_ms();
    int timeout_poll = -1; // Di base, poll blocca all'infinito se non c'è rete

    // 1. Calcolo dinamico del timeout di poll
    if (retry_timer.active) {
        long long tempo_rimasto = retry_timer.expiration_time - adesso;
        if (tempo_rimasto <= 0) {
            timeout_poll = 0; // Il timer è già scaduto! Poll deve solo fare un controllo istantaneo
        } else {
            timeout_poll = (int)tempo_rimasto; // Poll aspetterà AL MASSIMO questo tempo
        }
    }

    // 2. La chiamata a poll() - NON BLOCCA LA UI se impostata correttamente
    // Se passiamo ad esempio 5000, poll si sveglierà dopo 5 secondi OPPURE
    // immediatamente se arrivano dati sul socket della radio.
    int res = poll(fds, num_fds, timeout_poll);

    // 3. Controllo dei Timer Scaduti
    adesso = get_current_time_ms();
    if (retry_timer.active && adesso >= retry_timer.expiration_time) {
        retry_timer.active = 0; // Consumato
        
        // Prepariamo l'evento di TIME_ELAPSED
        Event ev = { .type = EV_TIME_ELAPSED, .payload = NULL };
        
        // "Imbuchiamo" l'evento nella mailbox dell'attore coordinatore
        send_message(retry_timer.target_actor, ev);
    }

    // 4. Dispatching dei messaggi tradizionali della Mailbox
    svuota_mailbox_attori();
}
`​`​`

## 💡 Perché questo meccanismo è perfetto?

Guarda cosa succede se imposti il retry a 5 secondi e usi questo approccio:

1. Il programma chiama `poll()` con un timeout di `5000`. Il kernel di macOS/Linux addormenta il thread risparmiando il 100% della CPU.
2. Se dopo 2 secondi l'utente preme il pulsante `STOP` sulla tastiera (o un comando arriva su un altro descrittore), `poll()` **si sveglia immediatamente in anticipo**.
3. Il ciclo intercetta il comando di `STOP`, lo invia al `Network Coordinator` che passa in stato `IDLE`.
4. Al giro successivo, l'Event Loop vedrà che la radio è ferma, annullerà il timer (`retry_timer.active = 0`) e non verrà effettuato nessun download fantasma.

> **Superpotenza macOS (`kqueue`):** Visto che compili su Mac, esiste un modo ancora più nativo. L'API di sistema `kqueue` ha un filtro interno chiamato `EVFILT_TIMER`. Puoi registrare un timer direttamente dentro `kqueue` passandogli il descrittore del socket. Il sistema operativo gestirà tutto e ti sveglierà la `kevent()` restituendoti un evento di tipo timer, esattamente come se fosse arrivato un byte dalla rete.

Abbracciare il timeout dinamico di `poll`/`select` ti permette di governare il tempo in C con la stessa identica eleganza asincrona di `setTimeout` in JavaScript, mantenendo l'applicazione leggera, reattiva e rigorosamente single-thread.
