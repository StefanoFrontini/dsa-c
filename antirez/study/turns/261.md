## ⚠️ L'ostacolo storico: Modalità Canonica vs Raw

Se provi ad aggiungere semplicemente `stdin` (che corrisponde al file descriptor `0` o alla costante `STDIN_FILENO`) a `poll()`, noterai un comportamento fastidioso: **`poll()` non si sbloccherà quando premi il tasto "a", ma solo quando premerai "a" seguito dal tasto Invio (Enter)**.

Questo accade perché, di default, il terminale lavora in **Modalità Canonica (Line-Buffered)**: accumula i caratteri in un buffer interno e li invia a `stdin` solo quando l'utente preme invio (permettendo di usare il tasto *Backspace* per correggere gli errori).

Per catturare i tasti all'istante, dobbiamo configurare temporaneamente il terminale in **Modalità Non Canonica (o Raw Mode)** usando la libreria standard `<termios.h>`.

## 🛠️ Come si configura il Terminale in C

Dobbiamo dire al sistema operativo di disattivare la modalità canonica e l'eco (il fatto che il terminale stampi a schermo il tasto che premi).

`​`​`c
#include <termios.h>
#include <unistd.h>

struct termios original_terminal_settings;

void disattiva_modalita_canonica(void) {
    struct termios raw;
    // Salva le impostazioni originali per ripristinarle alla fine
    tcgetattr(STDIN_FILENO, &original_terminal_settings);
    
    raw = original_terminal_settings;
    // Disattiva il buffer di riga (ICANON) e la stampa a schermo (ECHO)
    raw.c_lflag &= ~(ICANON | ECHO);
    
    // Applica le nuove impostazioni all'istante
    tcsetattr(STDIN_FILENO, TCSANOW, &raw);
}

void ripristina_terminale(void) {
    // FONDAMENTALE: altrimenti il terminale dell'utente rimarrà "rotto" alla chiusura del programma
    tcsetattr(STDIN_FILENO, TCSANOW, &original_terminal_settings);
}

## 🔄 La Coreografia dell'Event Loop nel Terminale

Ora che il terminale è configurato, possiamo popolare l'array di `poll()` con due elementi: `STDIN_FILENO` e il socket della radio. 

Guarda come diventa incredibilmente elegante e leggero il tuo `main` in C. La CPU rimarrà allo **0.0% di utilizzo** finché non tocchi la tastiera o non arriva un pacchetto audio.

`​`​`c
#include <poll.h>

void avvia_event_loop_terminale(int socket_radio, Actor *network_actor, Actor *player_actor) {
    disattiva_modalita_canonica();
    // Assicurati che il terminale venga ripristinato anche in caso di uscita improvvisa
    atexit(ripristina_terminale); 

    struct pollfd fds[2];
    
    // 1. Monitoriamo lo standard input (Tastiera)
    fds[0].fd = STDIN_FILENO;
    fds[0].events = POLLIN;

    // 2. Monitoriamo il socket di rete (Radio)
    fds[1].fd = socket_radio;
    fds[1].events = POLLIN;

    int programma_attivo = 1;

    while (programma_attivo) {
        int timeout_poll = calcola_timeout_dinamico_timer(); // Es. 5000 ms per il retry o -1

        // POLL BLOCCANTE: Il kernel di macOS addormenta il thread.
        // Si sveglia ISTANTANEAMENTE se premi un tasto o se arrivano byte dalla radio.
        int res = poll(fds, 2, timeout_poll);

        if (res > 0) {
            // CASO A: L'utente ha premuto un tasto!
            if (fds[0].revents & POLLIN) {
                char tasto;
                read(STDIN_FILENO, &tasto, 1); // Legge il singolo carattere all'istante
                
                if (tasto == 'q') {
                    programma_attivo = 0;
                } else if (tasto == 'a') {
                    // Spediamo un evento di Start/Stop all'attore del Player
                    Event ev = { .type = EV_TOGGLE_PLAY_STOP, .payload = NULL };
                    send_message(player_actor, ev);
                } else if (tasto == 'd') {
                    // Spediamo l'evento per tornare alla diretta
                    Event ev = { .type = EV_TORNA_A_DIRETTA, .payload = NULL };
                    send_message(network_actor, ev);
                }
            }

            // CASO B: Sono arrivati dati dal socket della radio!
            if (fds[1].revents & POLLIN) {
                // Notifichiamo l'attore di rete per leggere i dati
                Event ev = { .type = EV_DATI_RICEVUTI, .payload = NULL };
                send_message(network_actor, ev);
            }
        }

        // Gestione dei timer asincroni (es. scatta il retry se sono passati 5s)
        controlla_e_gestisci_timer_scaduti();

        // Svuotiamo le mailbox degli attori per far avanzare le loro macchine a stati
        svuota_mailbox_attori();
    }
}

## 💎 Perché questo è il Nirvana del C asincrono

Questo design è di una bellezza ingegneristica commovente:

1.  **Sincronizzazione perfetta dei canali:** Rete e Input utente viaggiano nello stesso imbuto di `poll()`. Non c'è alcun rischio di race condition tra ciò che l'utente clicca e ciò che la rete scarica, perché vengono letti sequenzialmente nello stesso giro di ciclo.
2.  **Addio `SDL_Delay`:** Non abbiamo più bisogno di quel micro-riposo forzato di `1 millisecondo` per evitare il 100% di CPU. È il kernel del sistema operativo, tramite la chiamata di blocco hardware di `poll()`, ad addormentare il processo e svegliarlo solo in presenza di reali elettroni sul bus della tastiera o della scheda di rete.
3.  **Portabilità estrema:** Questo codice non ha bisogno di dipendenze esterne. Gira nativamente su qualsiasi terminale Linux (inclusa la tua istanza Oracle Ubuntu) e macOS tramite SSH, consumando meno di 1 Megabyte di RAM per l'intera esecuzione.
